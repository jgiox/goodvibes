# Plan 16-01: managed-key JSON merge

## Objective

`goodvibes update` adds or refreshes only goodvibes-managed keys in a user-modified or user-owned
`.claude/settings.json` / `.mcp.json`, keeping every user key; untouched files keep whole-file overwrite.

## Decisions

- **Managed keys:** `permissions.ask` and `permissions.deny` entries (add-only union). Never `allow`: adding allow rules to a file the user edited widens permissions without consent. Hook groups whose command starts with `: goodvibes-<id>;` (added, or replaced in place). Template MCP servers (added, or template fields updated with user fields such as `headers` kept).
- **Identity:** a no-op `:` marker at the start of the hook command, because JSON has no comments and hook text changes between versions.
- **Opt-out survives:** `.goodvibes.json` gains `managed: {file: [ids]}`, the union of every id goodvibes has installed. An id recorded there but missing from the file was removed by the user and is not re-added. Old manifests have no record, so missing keys are added once.
- **Hash:** a merged file keeps its previous manifest hash (or `user-owned`), so it stays in the merge path instead of flipping to whole-file overwrite next run.
- **Invalid JSON:** reported in dry-run and in the summary, file left unchanged, update exits 0.

## Blocking fixes found during execution

1. `update` classed files that existed before `init` (never recorded) as net-new and overwrote them. Regression-first fix: keep them and record `user-owned`.
2. npm `init` crashed in the built CLI (`../../package.json`), so no npm project since 1.7.0 had a manifest and this phase could never run for npm users. Regression-first fix: `packageVersion()`.

## Verification

- npm and pip unit tests for the merge functions; real-tmpdir update tests for SC1-SC4, opt-out and invalid JSON.
- Built CLI and packed tarball exercised end to end on a hand-edited 1.7.1-style project.
