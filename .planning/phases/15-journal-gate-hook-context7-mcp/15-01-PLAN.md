<objective>
Ship the journal-gate `PreToolUse` hook (HOOK-01, HOOK-02, HOOK-03): an inline shell command in `.claude/settings.json` that blocks Claude Code's Bash tool from running `git commit` unless `JOURNAL.md` is staged, with documented exemptions and an actionable stderr message. </objective>

<notes>
## Dogfooding awareness (D-01) — going-forward workflow impact

This repo's established TDD convention (verified via git history) makes RED-only commits (`test(...): add failing test`) that touch only test files, never `JOURNAL.md`. Once this hook lands in `.claude/settings.json`, that convention will be blocked: any `git commit` run via Claude Code's Bash tool — including a RED-style commit — requires `JOURNAL.md` to be staged. This is the correct, intended behavior of the hook (HOOK-01/HOOK-02), not a bug. Going forward, RED-style commits made in this repo (by Claude Code) must include a trivial `JOURNAL.md` touch (or otherwise have `JOURNAL.md` staged) to pass the hook. Do not add a RED-commit exemption to the hook's exemption logic — HOOK-02's exemption list (`--amend`, merge-in-progress, rebase-in-progress, JOURNAL.md-already-staged) is locked, verified against RESEARCH.md, and must stay exactly as specified.
</notes>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude-generated Bash command -> hook stdin | The hook parses a JSON payload built from `tool_input.command`, which is ultimately model-generated text and could theoretically be shaped by prompt injection in conversation history |
| Hook shell script -> real git state | The script reads `.git` state (`MERGE_HEAD`, `rebase-merge`, `rebase-apply`, `diff --cached`) — untrusted only in the sense that a user/agent controls repo state, not a network boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Tampering | hook `--amend` exemption check | accept | Substring/regex match against raw command text can be spoofed by a commit message literally containing `--amend` (e.g. `git commit -m "docs: explain --amend"`); documented, low-severity limitation per RESEARCH.md Pitfall 2 — this is a self-inflicted-skip guardrail, not a security boundary, and HOOK-04's own docs wording already sets that expectation |
| T-15-02 | Tampering / Elevation of Privilege | hook shell script variable expansion | mitigate | Every variable expansion in the generated command (`"$CMD"`, `"$IN"`, `"$GITDIR"`) is double-quoted; no `eval` is used anywhere in the script — verified against the RESEARCH.md Code Examples source string before embedding |
| T-15-03 | Information Disclosure | stderr block message | accept | Message is fix-only text (JOURNAL.md path + git add command), contains no secrets, no stack traces, no environment details |
