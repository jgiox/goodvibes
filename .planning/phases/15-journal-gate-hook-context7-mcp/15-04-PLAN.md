<objective>
Close the HOOK-01/HOOK-02 verification gap recorded in `15-VERIFICATION.md` and `15-REVIEW.md` (CR-01, CR-02, WR-03): the journal-gate `PreToolUse` hook in `templates/.claude/settings.json` and `.claude/settings.json` matches `--amend` and the `git ... commit` subcommand via raw substring/regex search over the unparsed command text, which is bypassable two ways — (a) a genuine non-amend commit whose commit message merely contains the text `--amend` is incorrectly let through, and (b) a non-commit git command whose arguments merely contain the substring "git ... commit" is incorrectly blocked. Fix by stripping quoted spans (both `\"..\"` — the backslash-escaped double-quote form the JSON-extraction step already leaves in `$CMD` — and plain `'..'` single-quoted spans) out of the extracted command text before running either regex. Apply the identical fix to both `templates/.claude/settings.json` and `.claude/settings.json` (same duplicated hook logic in both, per CLAUDE.md's "check for all instances" rule), regenerate the gitignored npm prebuild mirror, and add the two adversarial test scenarios (RED before the fix, GREEN after) to both existing test suites so this defect class cannot silently regress.

Purpose: The journal-gate hook is the phase's core deliverable — a commit-time guardrail enforcing "update JOURNAL.md every task". A bypassable guardrail provides false confidence, which is worse than no guardrail (this is the exact defect class this gap-closure plan exists to remove).
Output: Fixed hook command embedded in both settings.json files (and the npm prebuild mirror), 4 new adversarial tests (2 npm + 2 pip — including a single-quote variant of the bypass, since the original two payloads in 15-REVIEW.md only exercised double-quoted messages) added to the existing test files, all 11 scenarios (9 original + 2 adversarial) green in both suites.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-04 | Tampering | hook `--amend`/commit-subcommand detection (the exact bug this plan fixes) | mitigate | Quoted-span stripping (`UNQUOTED` var) applied before both the `--amend` and the `git ... commit` regex checks, closing the CR-01 (false-negative bypass) and CR-02 (false-positive block) defects; verified against both exact reproduction payloads from 15-REVIEW.md plus a single-quote variant not covered by the original review |
| T-15-05 | Tampering | residual bypass surface: the quote-stripping regex itself is not a full shell-grammar parser | accept | The fix strips the two quoting forms that actually appear in `$CMD` after JSON extraction (backslash-escaped double quotes and plain single quotes) but does not handle nested/escaped quotes-within-quotes (e.g. a commit message containing an escaped literal `\"` inside an already-quoted span) or command substitution / variable expansion inside a quoted arg. This is an accepted, documented limitation consistent with the hook's original design intent (a lightweight commit-time nudge, not a shell parser) — a user or agent that wants to defeat a local pre-commit guardrail already has direct filesystem/git access and stronger bypass paths (e.g. `git commit --no-verify` equivalents don't even apply here since this is a Claude Code hook, not a git hook, but the agent could simply not use the Bash tool via Claude Code, or edit `.claude/settings.json` directly). Full shell tokenization was explicitly rejected to avoid adding a new required runtime dependency (`jq`/`python3`/`node`) to a hook shipped into every generated project regardless of language stack, per CLAUDE.md's "Language-agnostic core" constraint. |
| T-15-06 | Tampering | fix could introduce a new false-positive/negative if the sed clause order or escaping is wrong | mitigate | Both new sed clauses are additive (inserted between existing extraction and existing matching, no existing line altered) and were validated end-to-end against all 9 pre-existing scenarios plus both new adversarial scenarios and a single-quote variant before being written into the plan; Task 2's acceptance criteria require re-running the full 11-scenario suite in both packages, not just the 2 new cases, to catch any regression |
| T-15-07 | Elevation of Privilege | argv-tokenization alternative (rejected) | accept | The gap-closure scope offered "replace substring matching with real argv tokenization" as an alternative fix path; this plan does not take that path because introducing a `jq`/`python3`/`node`-based tokenizer as a new hard dependency of the shipped hook (which must run inside arbitrary user projects of any language) would violate CLAUDE.md's zero-config, language-agnostic constraints, and because `eval`-based or naive `set --`-based tokenization of untrusted, unescaped shell text is itself a well-known shell-injection vector — the quote-stripping approach uses no `eval` and no re-execution of extracted text as shell code, only as grep pattern input |
</threat_model>
