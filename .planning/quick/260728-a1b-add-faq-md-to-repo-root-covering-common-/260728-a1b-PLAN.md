    H2 headings for each question. Tone: friendly, assume the reader is new to terminals.

    Required sections (exact questions to use as H2 headings):

    **Q1: "Why does `goodvibes update` say version 1.6.1 even though I installed goodvibes-cli?"**
    Explain: goodvibes was originally published under the name `jgiox-goodvibes`. If the
    `goodvibes` command was installed before the rename, it still points to the old package.
    Symptoms to describe: the update header reads "goodvibes upgrade" (old alias),
    `goodvibes --version` prints 1.6.1, and running `uv tool upgrade goodvibes-cli` returns
    "goodvibes-cli is not installed" — because the binary at ~/.local/bin/goodvibes symlinks
    into uv/tools/jgiox-goodvibes, not goodvibes-cli.

    **Q2: "How do I fix it? (Package name migration from jgiox-goodvibes to goodvibes-cli)"**
    Provide the exact two-command fix, clearly labeled:
    ```
    uv tool uninstall jgiox-goodvibes
    uv tool install goodvibes-cli
    ```
    Add a fallback for users who installed with pip instead of uv:
    ```
    pip uninstall jgiox-goodvibes
    pip install goodvibes-cli
    ```
    After the fix, `goodvibes --version` should show 1.7.0 or higher. Tell the user to verify.

    **Q3: "What is the difference between `goodvibes update` and `goodvibes upgrade`?"**
    Explain: `goodvibes update` is the current command — it checks managed template files in
    the project and copies newer versions from the package. `goodvibes upgrade` was an older
    alias that existed in jgiox-goodvibes; if you see it in the command header, you are running
    the old package (see Q1). After migrating to goodvibes-cli, only `goodvibes update` exists.

    **Q4: "Why does `goodvibes update` say 'Already up to date' when I just installed?"**
    Explain: goodvibes tracks files by comparing SHA-256 hashes of each managed file. "Already
    up to date" means every template file in your project exactly matches the current package
    version — nothing needs to be written. This is normal after a clean init with the latest
    version. It does NOT compare CLI version numbers; it compares file content hashes.

    **Q5: "How do I check which goodvibes package I have installed?"**
    Provide:
    ```
    uv tool list
    ```
    If the output shows `jgiox-goodvibes`, follow the fix in Q2. If it shows `goodvibes-cli`,
    you are on the new package. Also mention: `goodvibes --version` always shows the CLI
    version regardless of which package it came from.

    Formatting rules:
    - Add a short one-paragraph intro at the top of the file before the first Q.
    - End with a "Still stuck?" section pointing to GitHub Issues URL:
      https://github.com/jgiox/goodvibes/issues
    - Keep the file under 120 lines.
    - No HTML. Pure markdown only.
    - Do not add a YAML front-matter block.
