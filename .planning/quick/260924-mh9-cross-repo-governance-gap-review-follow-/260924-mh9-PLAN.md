<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| goodvibes update process boundary | update writes hashes derived only from the goodvibes-controlled manifest and template source into .goodvibes.json; it must never let a maliciously modified dest file appear "unmodified" |
| Claude Code agent to human approval | templates/.claude/settings.json permissions decide which Bash commands an autonomous agent may run without asking a human |
| CI runner to public internet | security.yml pulls a third-party Docker image (gitleaks) and scans the full checked-out git history |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|--------------|------------------|
| T-mh9-01 | Tampering | write-manifest.ts / write_manifest.py preserved param | mitigate | preserved hashes are sourced only from the prior manifest, never from re-reading current dest content, so a user-modified file can never be reclassified as "unmodified" by the fix itself; existing assertSafe()/_assert_safe() path-traversal guard on manifest keys is unchanged |
| T-mh9-02 | Elevation of Privilege | templates/.claude/settings.json permissions | mitigate | add permissions.ask covering git push / npm,uv,twine publish / wrangler,vercel,netlify,firebase deploy so Claude Code's deny-then-ask-then-allow order stops the broad Bash(npx*)/Bash(uv*) allow rules from auto-approving deploys and publishes |
| T-mh9-03 | Tampering, Repudiation | security.yml gitleaks job | mitigate | scans full git history (fetch-depth 0) for committed secrets on every push/PR/schedule, catching a class of leak CodeQL does not cover |
| T-mh9-SC | Supply chain | npm/pip installs | not applicable | this plan adds no new npm or pip package dependencies; ruff runs via uvx (ephemeral) and gitleaks runs via a pinned Docker image tag (ghcr.io/gitleaks/gitleaks:v8.30.1), not a package-manager install — Package Legitimacy Gate does not apply |
</threat_model>
